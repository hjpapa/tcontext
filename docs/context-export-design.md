# Phase 3 설계: 컨텍스트 내보내기 개선 (전체본·핵심본·모듈 선택본)

- 기준 문서: 「TContext 고도화 개발 지침서 v1.0」(`instruct.md`) 5장, 10장 Phase 3
- 기준 코드: `main` @ `d4adc40` (Phase 1·2 병합 후)
- 상태: 9장 결정 확정(2026-10-26). 구현 운영 지침은 `docs/codex/runbook-phase3.md`에 있다. 설계 작성 단계에서는 코드를 변경하지 않았다.
- 범위: 세 가지 내보내기(전체본·핵심본·모듈 선택본), 모듈 선택 화면, 미리보기·복사·다운로드, 충실성 검사. AI 기반 요약·압축, skill 패키지의 모듈 분할, 버전 이력은 범위 밖이다(10장).
- Phase 3 완료 기준(지침서): 선택한 정보를 필요한 AI에 전달하면서 주요 교육적 원칙과 제약을 보존한다.

## 0. 핵심 결정 요약 (권장안)

1. **전체본은 지금의 `profileToMarkdown`을 그대로 쓴다.** 이 출력은 기여 API와 관리자 화면이 글자 단위로 대조하는 계약이므로 바꾸지 않는다.
2. **핵심본과 모듈 선택본은 AI 없이 규칙으로 만든다.** canonical JSON에서 교사가 검토한 문장을 **원문 그대로** 골라 배치만 한다. 그래서 "새로운 사실 추가"가 구조적으로 불가능하고, 개인정보 검사를 다시 받을 필요도 없으며, 같은 입력이면 출력이 같다.
3. **핵심본의 분량은 공통 고정 문구를 덜어내서 줄인다.** 수업 작업 양식, 실행 프롬프트, 자기 점검표, 갱신 안내처럼 모든 교사에게 같은 문구를 빼고, 확인되지 않은 문장을 제외한다. 교사의 문장은 자르거나 다시 쓰지 않는다.
4. **모듈 선택본은 "이 문서는 일부 모듈만 담고 있다"는 범위 안내를 반드시 넣는다.** AI가 빠진 영역의 교사 선호를 추측하지 않게 하기 위해서다. 메타데이터, 근거 표시 읽는 법, 개인정보 지침·경고, AI 협업 판단 경계는 선택과 관계없이 항상 넣는다.
5. **충실성 검사(지침서 5.4)는 검사 함수와 테스트로 고정한다.** 출력의 모든 내용 줄이 "고정 문구"이거나 "canonical 텍스트 원문"인지 기계적으로 확인한다.
6. **결과 화면에 "내보내기 형식" 패널을 추가한다.** 형식 선택, 모듈 체크박스, 미리보기, 복사, 다운로드를 제공한다. AI 활용 가이드의 Markdown 다운로드에서도 같은 형식을 고를 수 있게 한다.
7. **저장하지 않는다.** 변형본은 언제든 다시 만들 수 있으므로 IndexedDB에도, 기여 데이터에도 넣지 않는다. 선택 상태도 화면 메모리에만 둔다.

## 2. 세 가지 내보내기의 정의

### 2.1 공통 규칙

1. **입력은 확정본만 받는다.** 결과 화면처럼 `markdown`이 있는 세션 문서이거나, 로컬 기록의 확정본이다. 검사 대기 상태(`isPendingPrivacyReview`)이거나 `teacherContextProfileSchema` 검증에 실패하면 오류를 돌려준다.
2. **교사·AI 문장은 원문 그대로 쓴다.** 전체본과 같은 `sanitizeMarkdownText`만 적용한다. 자르기, 합치기, 바꿔 쓰기는 하지 않는다.
3. **근거 표시를 유지한다.** AI 추론 문장에는 항상 AI 해석 표시가 붙는다. 확인 필요 문장은 핵심본에 넣지 않고, 모듈 선택본에서는 전체본과 같이 `[검토 전]`으로 둔다.
4. **경고는 항상 넣는다.** 개인정보 "확인 안 됨"·"경고" 문구와, 미확인 문장이 있다는 경고를 넣는다. 문구는 전체본과 같은 의미로 쓴다.
5. **YAML 머리말**
   - 전체본과 같은 기본 필드를 쓴다: `document_type`, `title`, `profile_title`, `school_level`, `role`, `teaching_subject`, `schema_version`, `created_at`, `privacy_rule`, `privacy_review`, `needs_claim_review`.
   - 추가 필드
     - `export_variant`: `"core"` 또는 `"modules"`
     - `variant_format_version`: `"1.0"`
     - `context_as_of`: 3.5 참조
     - 모듈 선택본만: `included_modules`, `included_sections`
   - `document_format_version`은 쓰지 않는다. 전체본 2.0과 혼동하지 않게 하기 위해서다.
6. **결정적 출력**: 같은 입력이면 같은 문자열이 나온다. 시각은 입력으로 받는다.
7. **파일명**: 기존 패턴에 접미사를 붙인다.
   - 핵심본: `tcontext-teacher-profile-{level}-{yyyymmdd}-core.md`
   - 모듈 선택본: `tcontext-teacher-profile-{level}-{yyyymmdd}-modules.md`

### 2.2 전체본

- `profileToMarkdown(profile)`을 그대로 쓴다. 변경 없음.

### 2.3 핵심본 (`profileToCoreMarkdown`)

| 순서 | 섹션                          | 내용                                                                                                                                                                                                                                                              |
| ---- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 머리말                        | 2.1의 5                                                                                                                                                                                                                                                           |
| 2    | `# {profileTitle}`            | —                                                                                                                                                                                                                                                                 |
| 3    | `## 이 문서를 사용하는 방법`  | 고정 문구 5줄(새 상수 `CORE_USAGE_RULES`): 반복 사용하는 교사 핵심 맥락임 / 현재 요청 정보를 우선 / AI 해석은 확정 사실이 아님 / 개인정보를 추정·요구하지 않음 / 최종 판단은 교사                                                                                 |
| 4    | 경고                          | 개인정보 상태, 그리고 "확인되지 않은 문장 N개는 이 핵심본에서 제외했습니다. 전체본에서 확인할 수 있습니다." (N>0일 때)                                                                                                                                            |
| 5    | `## 요약`                     | `shortSummary`(비어 있으면 생략)                                                                                                                                                                                                                                  |
| 6    | `## 확인된 교사 맥락`         | 모듈 순서(`PROFILE_MODULE_IDS`)대로 `### {module.title}` + 모듈 요약 + **확인된 문장**(`confirmedByUser && basis !== "needs_confirmation"`). 앞에 `[직접]`·`[AI 해석·교사 승인]` 표시를 붙인다. 확인된 문장이 없는 모듈은 생략하고 4의 경고에 모듈 이름을 적는다. |
| 7    | `## 수업 설계 원칙`           | `teachingDesignPrinciples` 원문                                                                                                                                                                                                                                   |
| 8    | `## 학급 지원 고려사항`       | `classSupportConsiderations` 원문 + 기준 시점 표시(3.5)                                                                                                                                                                                                           |
| 9    | `## 현실적인 제약과 대체안`   | `realisticConstraints` 원문(**항상 전부**)                                                                                                                                                                                                                        |
| 10   | `## AI 협업 지침과 판단 경계` | `aiCollaborationInstructions` 원문(**항상 전부**)                                                                                                                                                                                                                 |

- 넣지 않는 것: 수업 작업 YAML, 실행 프롬프트, 자기 점검표, 갱신 안내, AI 우선순위 6개 목록, 분석 태그, 근거 질문 ID
- **중복 제거**
  - 공백을 정규화한 뒤 **완전히 같은 문장**만 제거한다. 앞에 나온 것을 남기며, 순서는 문장 → 원칙 → 지원 → 제약 → AI 지침이다.
  - 비슷한 문장을 하나로 합치는 의미적 중복 제거는 하지 않는다. AI가 필요하고 원문을 바꿀 수 있기 때문이다(9장 결정 1).
  - 제거한 개수는 출력하지 않는다. 같은 문장이 이미 위에 있기 때문이다.

### 2.4 모듈 선택본 (`profileToModuleMarkdown`)

- **선택 단위**
  - 7개 모듈(최소 1개)
  - 선택 섹션 3개: 수업 설계 원칙, 학급 지원 고려사항, 현실적인 제약과 대체안. 기본값은 모두 켜짐.
  - **항상 포함**: 머리말, 범위 안내, 근거 표시 읽는 법, 개인정보·미확인 경고, `## AI 협업 지침과 판단 경계`
- **구성**

| 순서 | 섹션                          | 내용                                                                                                                                                                                                       |
| ---- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 머리말                        | `included_modules`, `included_sections` 포함                                                                                                                                                               |
| 2    | `# {profileTitle}`            | —                                                                                                                                                                                                          |
| 3    | `## 이 문서의 범위`           | 고정 문구: "이 문서는 교사 프로파일 중 다음 영역만 담고 있습니다: {모듈 제목 목록}. 담기지 않은 영역에 대한 교사의 선호나 조건을 추측하지 말고, 필요하면 사용자에게 먼저 물어보세요." + `CORE_USAGE_RULES` |
| 4    | `## 근거 표시를 읽는 법`      | 전체본과 같은 의미의 3줄(새 상수로 둔다)                                                                                                                                                                   |
| 5    | 경고                          | 개인정보 상태, 그리고 **선택한 모듈 안에** 미확인 문장이 있을 때의 경고                                                                                                                                    |
| 6    | 선택한 모듈                   | 전체본의 모듈 섹션과 **같은 렌더링**: `## M{n}. 제목`, 요약, 근거별 묶음, `[검토 전]` 표시. 번호 `n`은 원래 모듈 번호를 유지한다.                                                                          |
| 7    | 선택 섹션                     | 켜진 섹션만 원문으로                                                                                                                                                                                       |
| 8    | `## AI 협업 지침과 판단 경계` | 항상                                                                                                                                                                                                       |

- **전체 요약(`shortSummary`)은 넣지 않는다.** 선택하지 않은 영역의 내용이 섞일 수 있기 때문이다(9장 결정 4).
- 전체본과의 일관성: 6의 모듈 섹션 문자열은 전체본의 같은 모듈 섹션과 **글자 단위로 같아야 한다**. 전체본 생성기는 고치지 않으므로, 테스트에서 전체본을 잘라 비교한다.

### 2.5 기준 시점 (`context_as_of`)

- 학급 맥락은 학기나 수업 집단이 바뀌면 낡는다(지침서 5.4의 다섯째 검사).
- 값
  - 로컬 기록에 연결된 문서는 기록의 `confirmed.confirmedAt` 날짜
    - 세션 연결 정보(`LocalProfileLink`)에는 이 값이 없다. 그래서 패널이 `getLocalProfile`로 기록을 읽어 가져온다.
    - 읽지 못하면 아래 규칙으로 대체한다.
  - 그 밖에는 `profile.metadata.generatedAt` 날짜
    - 수정을 거친 문서는 이 날짜가 실제보다 이를 수 있다. "작성 기준"이라는 표현을 쓴다.
  - 생성 함수는 날짜를 스스로 정하지 않는다. 호출하는 쪽이 `asOf`로 넘긴다.
- 표시 위치
  - 머리말 `context_as_of`
  - 핵심본 8번 섹션 제목 아래와 `class_context` 모듈 아래: "이 내용은 {YYYY-MM-DD} 기준입니다. 학기나 수업 집단이 바뀌면 다시 확인하세요."
  - 모듈 선택본에서 `class_context`를 고르면 같은 문장을 붙인다.

## 3. 충실성 검사 (지침서 5.4)

규칙 기반으로 만들기 때문에 다섯 가지 위험은 대부분 **구조로 막힌다.** 남는 위험은 구현 실수이므로 검사 함수로 잡는다.

| 지침서 검사                                        | 구조적 보장                                                           | 자동 검사                                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 교사가 말하지 않은 새로운 사실이 추가되지 않았는가 | 원문 선택·배치만 하고 생성하지 않음                                   | `verifyVariantFidelity`: 출력의 모든 내용 줄이 고정 문구 집합이거나 canonical 텍스트(정제 후) 원문과 같아야 한다 |
| 예외 조건이 누락되지 않았는가                      | 문장은 통째로 넣거나 통째로 빼며, 자르지 않음                         | 포함된 각 문장이 원문 전체와 같은지 확인. 빠진 문장은 "제외 규칙에 해당하는 것"뿐이어야 한다                     |
| 현실적 제약이 왜곡되지 않았는가                    | 핵심본은 제약을 항상 전부 넣음. 모듈 선택본은 섹션이 켜지면 전부 넣음 | 제약 항목 수와 원문 일치 확인                                                                                    |
| AI 추론이 확정 사실처럼 표현되지 않았는가          | AI 추론 문장에는 항상 표시를 붙임. 확인 필요 문장은 핵심본에서 제외   | `basis === "inferred"`인 문장이 표시 없이 나오면 실패                                                            |
| 오래된 학급 정보가 불변 조건처럼 제시되지 않았는가 | 학급 맥락에 기준 시점 문장을 붙임                                     | `class_context`나 학급 지원이 포함되면 기준 시점 문장이 있어야 한다                                              |

- 검사 함수는 `src/lib/export/profile-variants-fidelity.ts`에 둔다.
- 테스트에서는 모든 고정 데이터에 대해 실행한다: 가상 예시 4건, 문장 28개·종합 23개의 최대 크기 합성 프로필, 경고·확인 안 됨 상태, 미확인 문장, 여러 줄 문장, 중복 문장, 구형 프로필.
- 런타임에 다운로드를 막는 데는 쓰지 않는다(생성기가 결정적이므로 테스트로 충분하다).

## 4. 화면 설계

### 4.1 결과 화면: "내보내기 형식" 패널 (`src/components/export/export-variant-panel.tsx`)

- 위치: 기존 `ResultActions` 바로 아래. 제목은 "필요한 만큼만 전달하기"
- 형식 선택(라디오)
  - **전체본**: 모든 모듈과 수업 작업 양식. 처음 등록하거나 큰 작업에 적합
  - **핵심본**: 확인된 맥락과 원칙만. 반복 사용에 적합
  - **모듈 선택본**: 고른 영역만
- 모듈 선택본을 고르면
  - 7개 모듈 체크박스 + **전체 선택** / **전체 해제**
  - 선택 섹션 체크박스 3개
  - "AI 협업 지침과 판단 경계는 항상 포함됩니다" 안내
  - 모듈이 0개면 미리보기·복사·다운로드를 비활성화하고 "모듈을 하나 이상 고르세요"를 표시한다.
- **미리보기**: 실제 출력 문자열을 읽기 전용 영역(고정폭, 스크롤)에 보여주고, 글자 수를 표시한다. "다른 AI에는 이 내용이 그대로 전달됩니다"라는 안내를 붙인다.
- 버튼: **복사**, **Markdown 다운로드**
  - 실패 안내는 기존 `ResultActions`와 같은 방식으로 한다.
  - 다운로드는 `downloadTextFile`를 쓰고 BOM은 전체본과 같게 붙인다.
- 기존 버튼 처리(9장 결정 2): "짧은 AI 컨텍스트 복사"를 **"핵심본 복사"**로 바꾸고 새 핵심본을 복사한다. 나머지 버튼(Markdown 다운로드, 전체 컨텍스트 복사, 일반 텍스트 복사, 인쇄, JSON 백업)은 그대로 둔다.
- 상태는 컴포넌트 메모리에만 둔다. 저장하지 않는다.

### 4.2 AI 활용 가이드

- `GuideArtifacts`의 "교사 Markdown 다운로드" 옆에 형식 선택(전체본·핵심본·모듈 선택본)을 둔다.

## 9. 확정된 결정 사항 (2026-10-26)

1. **핵심본 생성 방식**: **확정: 규칙 기반(AI 없음).** 새로운 사실이 들어갈 수 없고, 개인정보 재검사·비용·응답 지연이 없다. 대신 비슷한 문장을 의미적으로 합치지는 못한다. AI 요약은 충실성 검사기를 갖춘 별도 단계로 미룬다.
2. **기존 "짧은 AI 컨텍스트 복사" 버튼**: **확정: "핵심본 복사"로 바꾼다.** 같은 목적의 기능이 두 개면 교사가 헷갈린다. `profileToCompactText` 함수는 남겨 두되 화면에서는 쓰지 않는다. 이 때문에 기존 RTL 테스트 1건(`result-actions.test.tsx`의 짧은 컨텍스트 복사)의 기대값을 바꿔야 한다.
3. **모듈 선택본의 종합 섹션**: **확정: 원칙·학급 지원·제약은 선택 항목(기본 켜짐), AI 협업 판단 경계는 항상 포함.**
4. **모듈 선택본의 전체 요약**: **확정: 넣지 않는다.** 선택하지 않은 영역의 내용이 섞일 수 있기 때문이다.
5. **AI 활용 가이드에도 형식 선택 제공**: **확정: 제공한다.** 대화 첨부(A) 방식에서 핵심본이 특히 유용하다.
6. **skill zip 참고 파일**: **확정: 전체본 유지.** 모듈별 참고 파일로 나누는 것은 Phase 4에서 Gemini의 참고 파일 열람 문제와 함께 다룬다.
7. **미확인 문장 처리**: **확정: 핵심본에서는 제외하고 개수를 표시한다. 모듈 선택본에서는 전체본처럼 `[검토 전]`으로 포함한다.**
