# 프롬프트 설계

## 공통 원칙

- 교사를 평가·진단·유형화하지 않는다.
- 답변에 없는 내용을 사실로 만들지 않는다.
- 개인 학생을 규정하지 않고 필요한 지원과 수업 조건을 기술한다.
- 직접 진술과 AI 해석을 명시적으로 구분한다.
- 자연스러운 한국어를 쓰되 과도한 미사여구와 AI 기술 용어를 피한다.
- 출력은 JSON Schema를 따르고 서버에서 Zod로 다시 검증한다.
- 모델 호출에는 가능한 경우 `store: false`를 사용한다.

프롬프트와 스키마는 `PROMPT_VERSION`, `PROFILE_SCHEMA_VERSION`으로 버전 관리한다. 현재 프롬프트 버전은 `1.1`이다. 환경 변수로 모델을 바꾸더라도 출력 스키마와 개인정보 기준은 유지한다.

## 후속 질문

기본 모델은 `OPENAI_INTERVIEW_MODEL=gpt-5-nano`, reasoning effort는 `minimal`이다. GPT-5 nano는 `none`을 지원하지 않으므로 지원되는 가장 낮은 단계를 사용한다.

입력:

- 학교급, 역할
- 현재 고정 질문 ID와 의도
- 현재 답변
- 지금까지 사용한 후속 질문 수
- 이미 물은 질문의 짧은 요약

행동:

1. 답변이 충분히 구체적인지 판단한다.
2. 구체적인 수업 경험을 한 번에 하나만 더 물을 가치가 있을 때만 질문한다.
3. 같은 내용을 반복하거나 교사를 평가하는 질문을 만들지 않는다.
4. 학생 이름, 학교명, 진단 정보 등 개인정보를 요구하지 않는다.
5. 전체 인터뷰에서 네 번째 후속 질문 이후에는 반드시 추가 질문 없음으로 응답한다.
6. 질문 하나에는 판단 하나만 담고, 최근 장면이나 한 가지 방법처럼 답변 범위를 좁힌다.
7. 강점은 행동과 맥락으로, 어려움은 에너지가 많이 드는 조건과 필요한 지원으로 묻는다.
8. 가벼운 유머는 보편적인 교실 현실에만 사용하고 학생의 어려움이나 평가 부담을 소재로 삼지 않는다.

출력:

- `needed`: boolean
- `question`: `prompt`, `intent`, `example`, `privacyHint`를 담은 객체 또는 null

## 최종 프로필 생성

기본 모델은 `OPENAI_PROFILE_MODEL=gpt-5.4-nano`, reasoning effort는 `low`다.

입력은 학교급, 역할, 질문 ID와 답변으로 제한한다. 서버는 원본을 저장하지 않고 요청 처리 후 폐기한다.

생성 규칙:

- 7개 모듈을 정해진 순서와 ID로 모두 만든다.
- 각 claim에 고유 ID, 문장, `direct | inferred | needs_confirmation`, 근거 질문 ID, 사용자 확인 상태를 담는다.
- 명시적인 진술은 `direct`, 충분한 근거가 있는 해석은 `inferred`, 근거가 약하거나 민감한 해석은 `needs_confirmation`으로 둔다.
- `inferred`와 `needs_confirmation`은 자동 확인하지 않는다.
- 학생 특성을 낙인 표현으로 일반화하지 않는다.
- 교사가 직접 밝힌 관심사, 실제 장면에서 관찰되는 강점, 어려움이 생기는 조건과 필요한 지원을 구분한다.
- 성격 특성이나 숨은 동기를 추정하지 않는다.
- 반복 문장을 합치되 서로 다른 근거를 잃지 않는다.
- 현실적 제약과 AI 협업 경계를 구체적 행동 지침으로 쓴다.
- controlled tag는 후보로만 생성하며 사용자 확인 전까지 저장 대상으로 보지 않는다.

## 프로필 수정

수정 모델은 프로필 모델 설정을 사용한다.

- 사용자가 지정한 claim 또는 섹션만 바꾼다.
- 이미 확인한 다른 claim의 문구, 근거, 확인 상태를 임의로 변경하지 않는다.
- 수정 요청에 개인정보가 포함되면 모델을 호출하지 않는다.
- 수정 결과 전체를 Zod로 검증하고 canonical JSON에서 Markdown을 다시 만든다.

## 개인정보 검토

기본 모델은 `OPENAI_PRIVACY_MODEL=gpt-5-nano`, reasoning effort는 `minimal`이다. GPT-5 nano는 `none`을 지원하지 않으므로 지원되는 가장 낮은 단계를 사용한다.

- 로컬 규칙 검사를 통과한 최종 프로필의 제목·요약·claim·원칙·지침 등 교사가 검토할 수 있는 자연어 필드만 `{path, text}`로 입력한다.
- 개인·학교·학급을 특정하거나 식별 가능한 개인과 성적·건강·상담 정보가 결합된, 구체적이고 높은 확신의 위험만 후보로 찾는다.
- 교사의 관심사·강점·어려운 조건, 익명 집단의 지원 맥락, 일반 수업 날짜·평균·순위 표현은 개인정보 후보로 보지 않는다.
- 모델은 후보의 경로·원문·범주·이유·대체 표현만 반환하고 상태를 정하지 않는다.
- 서버는 경로와 원문이 실제 입력 필드와 정확히 일치하는 후보만 채택한 뒤 `clear | needs_review` 상태를 계산한다.
- `needs_review` 상태에서는 문장을 수정해 다시 검사하거나, 명시적으로 경고를 확인한 뒤 로컬 결과만 만들 수 있다. 어느 경우에도 경고가 남은 결과의 선택 저장은 차단한다.

## 실패 처리

- 입력 스키마 오류: 400
- 개인정보 사전 탐지: 422, 모델 호출 없음
- 모델 시간 초과: 사용자에게 재시도 가능 메시지, 입력 본문 로그 금지
- Structured Output 또는 Zod 검증 실패: 내부 오류로 취급하고 원문 모델 출력을 응답·로그에 노출하지 않음
- 환경 변수 누락: 비밀값 없는 서비스 구성 오류 메시지

CI에서는 OpenAI 클라이언트를 모킹하며 실 API를 호출하지 않는다.
