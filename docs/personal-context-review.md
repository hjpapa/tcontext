# 개인 콘텍스트 목적에 대한 점검과 보완

## 목적과 기존 흐름

TContext의 결과물은 교사를 평가하는 보고서가 아니라, 교사가 AI에 매번 자신을 설명하는 부담을 줄이는 재사용 가능한 개인 콘텍스트다. 학교급·역할 선택 → 공통 및 분기 질문 → 필요한 후속 질문 → 구조화 JSON 생성 → 교사의 수정·삭제·확인 → Markdown 내보내기로 이어진다. JSON이 원본이고 내보내기는 로그인이나 데이터 기여 없이 동작한다.

기존 작업 중인 코드에는 이미 개인적 가치와 교육 원칙 문항이 있었다. 부족한 점은 가치의 이름보다 실제 선택 기준을 수집하는 깊이, AI에게 원하는 작업과 협업 방식의 근거였다. 계획 유지/변경의 양자 선택은 조건보다 유형처럼 읽힐 수 있었다. 생성 스키마는 모든 영역의 문장을 최소 하나 요구해 근거가 부족한 영역도 채우도록 유도했다.

## 이번 보완

핵심은 짧은 답변에서 풍부한 콘텍스트를 추론하는 것이다. 한 문장에 들어 있는 가치나 제약만으로도 관련 모듈의 실행 지침을 도출할 수 있다. 빈 영역 허용은 모든 답변에서 교차 추론할 단서조차 없는 경우에만 적용하며, 교사에게 자세한 답변을 강요하거나 AI를 요약기로 제한하기 위한 규칙이 아니다. 새 협업 방식은 AI 해석으로 적극 제안하되 이미 가진 개인적 선호라는 사실로 만들지 않는다.

- 개인적 가치가 드러나는 선택, 다른 요구와 원칙이 충돌할 때의 판단, 계획을 조정하는 관찰 신호를 묻는다.
- AI에게 맡길 작업과 원하는 응답 방식을 별도로 묻는다. 공통 12개·학교급 1개·역할 1개로 총 14개이며, 후속 질문 상한은 4개다. 신규 문항도 유치원 표현을 제공하고 건너뛸 수 있다.
- 개인적 가치 → 조건이 있는 판단 기준 → AI 협업 지침으로 연결한다. 지속적인 선호와 현재 학급·업무 조건을 구분하고, 답변에 없는 선호는 만들지 않는다.
- 근거 없는 모듈은 빈 claim 배열, 근거 없는 실행 목록은 빈 배열로 허용한다. 7개 모듈 구조와 기존 문서 스키마는 유지한다.
- 생성 및 수정 프롬프트는 요약과 실행 목록에서도 AI 해석·확인 필요를 표시하게 한다. 짧은 복사용 문서도 확인된 추론의 출처 구분을 유지한다.
- 현재 작업과 가치가 충돌하면 AI가 임의로 원칙을 지우지 않고 충돌과 대안을 설명하도록 내보내기 지침에 명시한다. 작업 양식의 수업 시간·차시 기본값은 미입력으로 바꾼다.

## 검증 범위와 후속 평가

질문 구성, 이전 질문 은행의 진행 위치 복원, 빈 근거 영역을 허용하는 구조화 출력, 가치·협업 선호와 추론 표시의 내보내기 및 삭제 반영을 자동 검사한다. 원본 답변의 미저장, 동의, 삭제, 내보내기 관련 기존 테스트도 함께 실행한다.

실제 모델의 개인화 품질은 자동 스키마 검증만으로 보장할 수 없다. 다음 사례를 실제 교사 답변으로 별도 평가할 필요가 있다.

1. 같은 학급 조건에서도 자율성 또는 예측 가능한 절차를 중시하는 교사의 제안이 각자의 근거에 맞게 달라지는가?
2. 원칙의 예외와 상황별 우선순위가 보존되는가?
3. AI를 써 본 적 없거나 가치 문항을 건너뛴 교사에게 임의의 선호를 부여하지 않는가?
4. 짧은 대안 비교를 원하는 교사와 자세한 단계 설명을 원하는 교사의 지침이 구분되는가?
5. 교사가 문장을 수정·삭제한 뒤 요약과 실행 목록에 같은 의미가 남아 있지 않은지 함께 검토할 수 있는가?

개인화의 의미 보존은 여전히 모델 프롬프트와 교사 검토에 의존한다. 원본 답변을 보관하지 않으므로 서버에 평가용 실제 인터뷰를 축적하지 않으며, 라이브 모델 평가는 별도 실행한다.
