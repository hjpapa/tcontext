# 개인정보 보호 설계

## 기본 원칙

TContext는 데이터 최소화, 목적 제한, 사용자 검토, 선택 동의를 기본값으로 삼는다. 서비스 이용과 Markdown 다운로드에는 로그인이나 데이터베이스 저장이 필요하지 않다.

입력해서는 안 되는 정보:

- 교사·학생 이름, 구체적인 학교명, 반·학급을 특정하는 명칭
- 전화번호, 이메일, 주소, 생년월일, 주민등록번호 형식
- 학생 사진, 연락처, 상담·건강·진단·가정환경·생활기록부 내용
- 여러 정보의 조합으로 특정 개인을 추정할 수 있는 서술

학생을 규정하는 표현 대신 필요한 지원과 관찰 가능한 수업 조건을 기술하도록 안내한다.

## 단계별 데이터 흐름

### 1. 브라우저 입력

- 원본 답변 문자열은 React 메모리에만 두며 Web Storage, 쿠키, IndexedDB에 기록하지 않는다.
- `sessionStorage`에는 학교급·역할·현재 질문 위치 같은 비민감 진행 메타데이터만 저장한다.
- 새로고침하거나 탭을 닫으면 원본 답변을 복구할 수 없음을 인터뷰 화면에서 안내한다.
- `localStorage`에는 원본 답변이나 생성 프로필을 저장하지 않는다.
- “모든 기록 삭제”로 TContext 진행 메타데이터를 즉시 지울 수 있다.

### 2. AI 전송 전

- 클라이언트 규칙 기반 탐지기가 이메일, 전화번호, 유효한 주민등록번호 형식, 생년월일 표지가 붙은 날짜, 구체 주소·학교명, 실명 가능 표현과 개인에게 연결된 민감정보를 검사한다.
- 일반 일정 날짜, 평균 점수, 수업 아이디어의 순위 표현, 익명 집단을 위한 건강·학습 지원처럼 개인을 특정하지 않는 교육 맥락은 식별정보로 차단하지 않는다.
- 위험이 탐지되면 답변을 서버나 OpenAI로 전송하지 않는다.
- 문제 구간, 이유, 지원 중심 대체 문장 예시를 보여주고 사용자가 직접 수정한 뒤 재제출하도록 한다.

### 3. 서버와 OpenAI

- OpenAI 호출은 Next.js Route Handler에서만 수행한다.
- 공식 Responses API와 JSON Schema Structured Outputs를 사용한다.
- 가능하면 `store: false`를 적용한다.
- 서버에서도 동일한 개인정보 규칙을 다시 검사한다.
- 교사가 초안을 검토한 뒤 별도 개인정보 검토 모델을 실행한다. 모델에는 사용자가 읽고 수정할 수 있는 제목·요약·문장·지침만 필드 경로와 함께 보낸다.
- 모델이 반환한 경로와 원문이 실제 검토 필드와 정확히 일치하는 항목만 채택하고, 최종 상태는 서버가 계산한다. 메타데이터, 내부 ID, 태그, 과거 검사 결과는 이 검토 입력에 포함하지 않는다.
- 애플리케이션 로그에는 질문, 답변, 프로필 본문을 남기지 않는다. 모델명, 처리 시간, 토큰 사용량, 성공 여부만 구조화해 기록한다.

### 4. 최종 경고와 로컬 결과

- 최종 검사에서 `needs_review`가 나오면 사용자는 문장을 수정·삭제하고 다시 검사할 수 있다.
- 교육 맥락상 남겨야 하는 표현이라면 위험을 직접 확인했다는 명시적 체크 후, 상태를 `clear`로 바꾸지 않고 브라우저 메모리에서 결과를 만들 수 있다.
- 이 경로에서도 Markdown과 복사 기능은 사용할 수 있지만 선택적 Supabase 기여는 UI와 서버에서 모두 차단한다.
- 프로필을 수정하면 이전 검사 결과와 경고 확인, 생성된 Markdown을 모두 무효화한다. 과거 경고 문구를 새 검사 대상으로 다시 사용하지 않는다.

### 5. 선택적 Supabase 저장

- 체크박스는 기본 해제 상태다.
- 저장 목적, 항목, 일일 정리 간격을 포함한 최대 365일 실제 보유기간을 확인하고 명시적으로 동의한 경우에만 저장한다.
- canonical 최종 프로필 JSON, 동일 JSON에서 만든 Markdown, 교사가 확인한 태그, 개인정보 검토 결과와 운영 메타데이터만 저장한다.
- 원본 인터뷰의 전사본이나 별도 답변 필드, 이름, 이메일, IP 주소, 학교명, 학생명, 브라우저 식별자는 저장하지 않는다. 교사가 검토·승인한 최종 프로필에는 인터뷰에서 확인한 수업 맥락의 요약이 포함될 수 있다.
- `SUPABASE_SECRET_KEY`는 서버 전용 모듈에서만 읽는다. 브라우저 번들에 포함하지 않는다.
- RLS를 강제하고 `anon`, `authenticated`, `public`에는 읽기·쓰기 정책이나 테이블 권한을 주지 않는다.

## 삭제 코드

저장 시 서버가 충분히 긴 무작위 코드를 만들고, 브라우저에는 원문을 한 번만 반환한다. 데이터베이스에는 서버 비밀값과 결합한 SHA-256/HMAC 해시만 저장한다. 사용자는 제출 ID와 삭제 코드로 `/delete`에서 삭제할 수 있으며, 공개 조회 API는 제공하지 않는다.

삭제 코드 분실 시 로그인 계정이나 이메일이 없으므로 제출물을 찾아주거나 삭제하기 어려울 수 있다.

## 보유기간과 자동 삭제

- `DATA_RETENTION_DAYS`는 일일 정리 지연까지 포함해 행이 실제로 저장될 수 있는 최장 일수이며 기본값과 하드 상한은 365일이다.
- `retention_until = consented_at + max(DATA_RETENTION_DAYS - 1, 0)일`로 계산해 매일 실행되는 정리 작업을 위한 최대 하루를 정책 기간 안에 확보한다.
- 기본값 365에서는 동의 364일 뒤 삭제 대상으로 전환하고, 다음 일일 정리 주기까지 포함해 실제 보유기간이 최대 365일을 넘지 않게 한다.
- 값이 1이면 동의 즉시 삭제 대상으로 전환하고 다음 일일 정리 주기 안에 삭제한다.
- Vercel Cron이 매일 보호된 API를 호출해 `retention_until < now()`인 행을 삭제한다. 사용자는 삭제 코드로 그보다 먼저 삭제할 수 있다.
- Cron 응답과 로그에는 삭제 건수만 포함하고 프로필 본문은 포함하지 않는다.

## 로그 정책

허용:

- 요청 유형, 모델명, 성공 여부, 처리 시간, 토큰 사용량
- 개인정보 탐지 발생 여부와 규칙 식별자
- 저장·삭제 성공 여부와 건수

금지:

- 원본 인터뷰 답변
- 프로필 JSON 또는 Markdown 본문
- 삭제 코드, 해시, Supabase Secret Key, OpenAI API Key
- 이름, IP 주소, 학교명 등 식별 가능 정보

## 탐지기의 한계

규칙 기반 탐지는 모든 실명·문맥상 식별 정보·변형 표기를 찾을 수 없다. AI 검토 역시 완전한 보장을 제공하지 않는다. 그래서 두 탐지 단계를 보조 장치로만 사용하고, 교사의 최종 확인과 “저장하지 않기” 선택을 가장 중요한 통제로 둔다.
