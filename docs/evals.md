# 평가와 테스트 전략

## 품질 축

짧은 답변에 대한 핵심 평가: "스스로 생각하는 게 중요해요"에서 질문·생각할 시간·단계별 힌트, "준비할 시간이 없어요"에서 자료 재사용·준비 단계 축소 같은 서로 다른 실행 지침을 추론해야 한다. 단순 재진술이나 빈 모듈 위주의 결과는 불충분하다. "공정함"처럼 설계 방향이 갈리는 단서는 선택이 필요한 가설로 구분한다. 존재하지 않는 시간·기기·활동 이력을 사실로 만드는 결과는 실패다.

모의 응답 테스트는 짧은 답변에서 생성된 교차 모듈 추론과 실행 지침이 검증·내보내기를 거쳐 보존되는지를 확인한다. 이는 실제 모델의 추론 품질 평가를 대신하지 않는다.

| 축          | 통과 기준                                                                                                                               |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 충실성      | 모든 주요 claim이 근거 질문 ID를 갖고, 답변에 없는 사실을 만들지 않는다.                                                                |
| 증거 구분   | 직접 진술·추론·확인 필요가 올바르게 구분되고 후자의 둘은 자동 확인되지 않는다.                                                          |
| 개인정보    | 실제 식별정보는 모델 호출 전에 차단되고, 경고 결과는 로컬 내보내기만 가능하며 최종 저장은 `privacyReview.status=clear`일 때만 가능하다. |
| 비낙인 표현 | 학생을 고정 특성으로 규정하지 않고 관찰 가능한 조건과 필요한 지원을 기술한다.                                                           |
| 구조        | 7개 모듈, 메타데이터, 지침, 제약, 태그, 개인정보 검토가 Zod를 통과한다.                                                                 |
| 교사 통제   | 모든 claim·태그와 AI 작성 제목·요약·원칙·지침을 수정·삭제·확인할 수 있다.                                                               |
| 이식성      | Markdown이 특정 AI 제품 명령어에 종속되지 않고 YAML front matter를 포함한다.                                                            |
| 접근성      | 키보드만으로 핵심 흐름을 완료하고 상태가 색상 외 텍스트·아이콘으로 전달된다.                                                            |

## 단위 테스트

- 학교급·역할별 질문 분기, 중고등학교 담당 교과 전달과 공통 12개·학교급 1개·역할 1개의 정확한 구성
- 유치원 공통 질문이 유아·놀이·일과·관찰 맥락의 쉬운 표현으로 바뀌는지 확인
- 인터뷰 진행률, 이전·다음 이동, 건너뛰기, 후속 질문 총 4회 제한
- 이메일·전화번호·유효한 주민번호 형식·표지가 있는 생년월일·주소·실명 가능 표현 탐지
- 일반 일정 날짜·평균 점수·교육 맥락의 순위와 `학생`·`학급`·`우리 반`을 포함한 익명 집단 지원 문구가 개인정보로 오탐되지 않는지 확인
- AI 개인정보 검토가 실제 필드 경로·원문과 구체적 식별 단서가 모두 일치하는 항목만 채택하는지 확인
- 프로필 생성이 모듈당 2~4개 claim, 실제 근거 질문 ID, 직접 진술·추론·확인 필요 구분을 지키는지 확인
- 모듈 재작성에서 확인 완료 claim과 근거 ID를 보존하고 출력 한도 응답을 더 큰 한도로 재시도하는지 확인
- 학생 규정 표현을 지원 중심 표현으로 바꾸는 보조 함수
- `TeacherContextProfile` Zod 검증과 7개 모듈 불변식
- 미확인 태그 제거
- canonical JSON에서 문서 형식 2.0 Markdown, 수업 작업 YAML, 실행 프롬프트, 파일명 생성과 특수문자 처리
- 관리자 열람에서 현재 Markdown과 이미 저장된 구형 Markdown은 허용하고 변조된 Markdown은 거부
- 삭제 코드 생성·해시 비교와 보유기간 계산
- Supabase payload에서 원본 인터뷰 답변이 제외되는지 확인

## API 테스트

- 잘못된 JSON 또는 스키마 입력은 400
- 개인정보 탐지 시 OpenAI 호출 없음
- Structured Output 검증 실패와 타임아웃의 안전한 오류 처리
- 동의 누락, 미완료 개인정보 검토, 미확인 claim·태그, JSON/Markdown 불일치 시 저장 거부
- 정상 저장은 제출 ID와 원문 삭제 코드를 한 번만 반환
- 잘못된 삭제 코드는 거부하고 올바른 코드는 행을 삭제
- 로그에 질문·답변·프로필 본문·비밀값이 포함되지 않음

## E2E 시나리오

1. 초등 담임 전체 인터뷰 → 프로필 생성 → 근거별 검토 → 태그 확인 → Markdown 다운로드 → 저장 거부 후 정상 종료
2. 유치원 분기 질문과 개인정보 경고·수정
3. 중·고등학교 분기와 최대 후속 질문 제한
4. 선택 저장 → 영수증 다운로드 → 삭제 코드로 익명 삭제
5. 모든 브라우저 기록 삭제
6. 360px 모바일과 데스크톱 레이아웃, 키보드 탐색, reduced-motion
7. 최종 `needs_review` → 수정 후 재검사 또는 명시적 경고 확인 → 로컬 다운로드, 선택 저장 차단
8. 접힌 답변 예시를 필요할 때만 열고, 모듈 단위 AI 재작성 후에도 직접 수정·삭제 가능
9. 모듈 재작성 실패 시 기존 초안과 지시문 보존, 재작성 중 직접 수정 시 늦은 AI 결과 폐기
10. 최종 AI가 일반적인 `학생`·`학급` 표현을 후보로 반환해도 개인정보 경고로 채택하지 않음
11. 예시와 최종 결과에서 수업 작업 YAML·AI 실행 지침을 확인하고 데스크톱·모바일에서 접힘과 내보내기 동작 검증
12. 모듈 재작성 오류와 최종 개인정보 경고에서 해당 입력으로 이동하고, 확인 대화상자를 거쳐 미확인 문장을 한 번에 승인한 뒤 키보드 포커스가 유지되는지 검증

## 자동화 명령

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

CI는 실제 OpenAI API와 Supabase 운영 DB를 호출하지 않는다. 배포 후에는 별도의 수동 스모크 테스트로 모델 연결과 선택 저장·삭제를 검증한다.
